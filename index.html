1 Introduction to HTML

What is HTML?

HTML stands for HyperText Markup Language. It is the standard markup language used to create and structure content on the World Wide Web. Every website you visit is built using HTML at its core.

  • HyperText — Refers to text that contains links (hyperlinks) to other text or resources
  • Markup — A system of annotating content to define its structure and meaning
  • Language — A set of rules and syntax for writing these annotations
💡
Key Point: HTML is NOT a programming language — it is a markup language. It doesn't have logic, loops, or variables. It simply describes the structure and content of a webpage.

History of HTML

HTML was created by Tim Berners-Lee in 1991 at CERN. Since then, it has evolved significantly:

HTML 1.0 (1991)

The original version. Very basic — supported text, links, and simple formatting. Only 18 elements.

HTML 2.0 (1995)

First standard specification by IETF. Added forms and tables.

HTML 3.2 (1997)

W3C recommendation. Added scripts, applets, text flow around images, and tables.

HTML 4.01 (1999)

Major version with CSS support, accessibility features, and three variants: Strict, Transitional, Frameset.

XHTML 1.0 (2000)

HTML reformulated as XML. Stricter syntax rules. Required lowercase tags and quoted attributes.

HTML5 (2014)

Revolutionary update! New semantic elements, multimedia support, Canvas, APIs, form controls, and much more.

HTML 5.2 (2017)

Added <dialog> element, Payment Request API, and various improvements.

HTML Living Standard (Now)

HTML is now a "living standard" maintained by WHATWG, continuously updated.

Who Maintains HTML?

Two organizations are central to HTML's development:

OrganizationFull NameRole
W3CWorld Wide Web ConsortiumPublished HTML specifications from HTML 2.0 through HTML 5.2
WHATWGWeb Hypertext Application Technology Working GroupMaintains the HTML Living Standard (current authority)
✅
Current Status: Since 2019, W3C and WHATWG agreed that the WHATWG Living Standard is the single authoritative version of HTML.

How Browsers Render HTML

When you open a webpage, the browser performs these steps:

  1. Fetch — Downloads the HTML file from the server
  2. Parse — Reads the HTML and creates the DOM (Document Object Model)
  3. Parse CSS — Builds the CSSOM (CSS Object Model)
  4. Render Tree — Combines DOM + CSSOM into a render tree
  5. Layout — Calculates the position and size of each element
  6. Paint — Draws pixels to the screen

Basic HTML Document

Here is the simplest complete HTML document:

HTML
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First Page</title>
</head>
<body>
  <h1>Hello, World!</h1>
  <p>This is my first webpage.</p>
</body>
</html>

2 HTML Basics & Document Structure

Elements, Tags & Attributes

Understanding these three concepts is fundamental to HTML:

Elements

An HTML element is the complete unit — from opening tag to closing tag, including content:

<p class="intro" > Hello World </p>
↑ Opening Tag ↑ Attribute ↑ Content ↑ Closing Tag
← The entire thing is an ELEMENT →

Tags

Tags are the markup that surrounds content. There are three types:

TypeExampleDescription
Opening Tag<p>Begins an element
Closing Tag</p>Ends an element (note the /)
Self-Closing Tag<br>, <img>No closing tag needed (void elements)

Attributes

Attributes provide additional information about an element. They appear in the opening tag:

HTML
<a href="https://example.com" target="_blank" rel="noopener">Click me</a>
<img src="photo.jpg" alt="A sunset" width="300">

The DOCTYPE Declaration

The <!DOCTYPE html> declaration must be the very first line in every HTML document. It tells the browser to use HTML5 standards mode.

⚠️
Important: Without DOCTYPE, browsers enter "quirks mode" which renders pages using old, inconsistent rules. Always include it!

Document Structure: html, head, body

  • <head> — Contains metadata (not visible on page)

Comments are ignored by the browser and used for developer notes:

Block-Level vs Inline Elements

Block-Level Elements

  • Start on a new line
  • Take full width available
  • Can contain other block & inline elements
  • Examples: <div>, <p>, <h1>, <section>, <ul>

Inline Elements

  • Do NOT start on a new line
  • Only take up as much width as needed
  • Should only contain data or other inline elements
  • Examples: <span>, <a>, <strong>, <em>, <img>

        content="A brief description">
  <title>Page Title</title>                  <!-- Browser tab title -->

</body>                                   <!-- End of visible content -->
</html>                                   <!-- End of document -->

10 Semantic HTML5

What is Semantic HTML?

Semantic HTML uses tags that convey meaning about the content they contain — not just how it looks. Instead of using <div> for everything, semantic elements tell browsers, search engines, and assistive technologies what each section represents.

❌ Non-Semantic

<div class="header">...</div>
<div class="nav">...</div>
<div class="main">...</div>
<div class="footer">...</div>

✅ Semantic

<header>...</header>
<nav>...</nav>
<main>...</main>
<footer>...</footer>

Semantic Page Layout

<header>
<nav>
<main>
<article>
<section>

<footer>

12 HTML Entities & Special Characters

What are HTML Entities?

HTML entities are special codes used to display characters that have special meaning in HTML (like < and >) or characters not easily typed on a keyboard.

Entities start with & and end with ;:

HTML
<!-- Wrong: browser thinks < is a tag -->
<p>Use <p> tag for paragraphs</p>  ❌

<!-- Right: use entities -->
<p>Use &lt;p&gt; tag for paragraphs</p>  ✅

13 Accessibility (a11y)

Why Accessibility Matters

Web accessibility (a11y) means designing websites that can be used by everyone — including people with disabilities. Over 1 billion people worldwide have some form of disability.

♿
WCAG: The Web Content Accessibility Guidelines (WCAG) are the international standard. Aim for WCAG 2.1 Level AA compliance.

The 4 Principles of Accessibility (POUR)

PrincipleMeans
PerceivableUsers must be able to perceive the information (alt text, captions, contrast)
OperableUsers must be able to operate the interface (keyboard navigation, no traps)
UnderstandableContent and operation must be understandable (clear language, predictable UI)
RobustContent must work with current and future assistive technologies

ARIA (Accessible Rich Internet Applications)

ARIA attributes enhance accessibility when semantic HTML isn't enough.

⚠️
First Rule of ARIA: Don't use ARIA if a semantic HTML element exists that does the job. Use <button>, not <div role="button">!
AttributePurposeExample
aria-labelAccessible name for element<button aria-label="Close">×</button>
aria-labelledbyReferences element that labels itaria-labelledby="title-id"
aria-describedbyReferences descriptive elementaria-describedby="help-text"
aria-hiddenHide from assistive techaria-hidden="true"
aria-liveAnnounce dynamic changesaria-live="polite"
aria-expandedExpanded/collapsed statearia-expanded="false"
aria-currentCurrent item in setaria-current="page"
roleExplicitly define rolerole="alert"

Accessibility Checklist

✅ Use semantic HTML

Prefer <button>, <nav>, <header> over <div>

✅ Add alt text

Every image needs descriptive alt text

✅ Label form inputs

Every input needs an associated <label>

✅ Use heading hierarchy

h1 → h2 → h3, don't skip levels

✅ Keyboard navigable

Everything accessible via Tab key

✅ Focus indicators

Visible focus styles on interactive elements

✅ Color contrast

4.5:1 for normal text, 3:1 for large text

✅ Don't rely on color alone

Use icons/text in addition to color

✅ Set language

<html lang="en"> for screen readers

✅ Descriptive links

Not "click here" — describe the destination

✅ Caption media

Captions for videos, transcripts for audio

✅ Test with tools

Lighthouse, WAVE, axe DevTools

❌ Bad

14 SEO & HTML

What is SEO?

SEO (Search Engine Optimization) is the practice of making your website rank higher in search engine results. HTML plays a huge role in SEO because search engines parse your HTML to understand your content.

Essential SEO Elements

HTML
<head>
  <!-- Unique, descriptive title (50-60 chars) -->
  <title>Learn HTML — Complete Tutorial for Beginners</title>

  <!-- Meta description (150-160 chars) -->
  <meta name="description"
        content="Master HTML with our complete guide. Learn tags, attributes, forms, semantic HTML, and more with hands-on examples.">

  <!-- Canonical URL (avoid duplicate content) -->
  <link rel="canonical" href="https://example.com/html-tutorial">

  <!-- Robots meta -->
  <meta name="robots" content="index, follow">

  <!-- Language -->
  <html lang="en">
</head>

Structured Data (JSON-LD)

Helps search engines understand your content type for rich snippets:

HTML
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Complete HTML Guide",
  "author": {
    "@type": "Person",
    "name": "Jane Doe"
  },
  "datePublished": "2024-01-15",
  "image": "https://example.com/image.jpg"
}
</script>

SEO Best Practices Checklist

  • ✅ Unique titles — Each page should have a unique, descriptive <title>
  • ✅ Meta descriptions — Compelling 150-160 char descriptions
  • ✅ Single H1 — One <h1> per page containing the main topic
  • ✅ Heading hierarchy — Logical h1 → h2 → h3 structure
  • ✅ Alt text — Descriptive alt attributes on all images
  • ✅ Semantic HTML — Use <article>, <nav>, <main> appropriately
  • ✅ Fast loading — Lazy load images, minify assets
  • ✅ Mobile-friendly — Responsive viewport meta tag
  • ✅ HTTPS — Secure connection boosts rankings
  • ✅ Internal linking — Link related pages with descriptive anchor text
  • ✅ Sitemap — Submit sitemap.xml to Google Search Console
  • ✅ robots.txt — Control which pages are crawled
  • ✅ Structured data — Schema.org JSON-LD for rich snippets

15 HTML Best Practices

Code Quality Best Practices

  1. Always declare DOCTYPE — <!DOCTYPE html> at the top
  2. Use lowercase tags — <div> not <DIV>
  3. Quote attribute values — class="btn" not class=btn
  4. Close all elements — Even in HTML5 where optional
  5. Use semantic tags — Convey meaning, not just structure
  6. Indent consistently — 2 or 4 spaces, be consistent
  7. Add comments — Document complex sections
  8. Validate your HTML — Use W3C Validator
  9. Separate concerns — HTML for structure, CSS for style, JS for behavior
  10. Specify language — <html lang="en">

Performance Best Practices

HTML
<!-- 1. Lazy load images below the fold -->
<img src="photo.jpg" loading="lazy" alt="...">

<!-- 2. Set width/height to prevent layout shift -->
<img src="photo.jpg" width="800" height="600">

<!-- 3. Use defer for non-critical scripts -->
<script src="app.js" defer></script>

<!-- 4. Preconnect to third-party origins -->
<link rel="preconnect" href="https://fonts.googleapis.com">

<!-- 5. Preload critical resources -->
<link rel="preload" href="hero.jpg" as="image">

<!-- 6. Use responsive images -->
<img srcset="small.jpg 400w, large.jpg 1200w" sizes="100vw">

<!-- 7. Use modern image formats -->
<picture>
  <source srcset="image.avif" type="image/avif">
  <source srcset="image.webp" type="image/webp">
  <img src="image.jpg" alt="...">
</picture>

Security Best Practices

🔒
Key Security Tips:
  • Always use rel="noopener noreferrer" with target="_blank"
  • Sanitize user input before inserting into HTML (prevent XSS)
  • Use sandbox attribute on iframes when possible
  • Set Content Security Policy (CSP) headers
  • Use HTTPS everywhere
  • Never put secrets (API keys, passwords) in HTML

Mobile-First Responsive Design

HTML
<!-- Essential viewport meta tag -->
<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

<!-- Theme color for mobile browsers -->
<meta name="theme-color" content="#2563eb">

<!-- Apple touch icon -->
<link rel="apple-touch-icon" href="icon-180.png">

<!-- Manifest for PWA -->
<link rel="manifest" href="manifest.json">

Common Mistakes to Avoid

❌ Don't

  • Use tables for layout
  • Use <br> for spacing
  • Skip heading levels
  • Use inline styles
  • Nest links inside links
  • Forget alt text
  • Use "click here" for links
  • Mix tabs and spaces

✅ Do

  • Use CSS Grid/Flexbox for layout
  • Use CSS margin/padding for spacing
  • Maintain logical heading order
  • Keep styles in CSS files
  • Keep link structures clean
  • Always add descriptive alt text
  • Write descriptive link text
  • Use consistent indentation

16 Deprecated & Obsolete Elements

What is "Deprecated"?

Deprecated elements are old HTML features that should no longer be used. They may still work in browsers for backward compatibility, but they're considered obsolete in HTML5.

⚠️
Rule: Never use deprecated elements in new projects. They can cause validation errors, accessibility issues, and may stop working in future browsers.
